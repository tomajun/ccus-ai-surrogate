## 一、项目方向（我们在做什么，为什么）

**一句话**：用轻量级深度学习，把 CO₂ 地质封存中**很贵、很慢**的地下羽流仿真，替换成**几毫秒即可出结果**的代理模型，并额外给出"封存会不会漏、有多大把握"的风险判断。

更完整地讲，项目落在 CCUS（碳捕集、利用与封存）链条的**封存段**：

- **输入**：3 个工程/地质参数——注入速率 Q、盖层渗透性 k、储层厚度 H；
- **输出①**：CO₂ 饱和度羽流场（随时间演化，48×48 网格）；
- **输出②**：泄漏风险三档评级（低 / 中 / 高）+ 置信区间。

**选择该方向的理由（如实说明）**：
1. 契合国家"双碳"战略，立项与答辩有政策顺风；
2. GitHub 上"CCUS + 机器学习"细分近乎空白，同质化低、辨识度高；
3. 我们刻意把规模压到**本科可独立闭环**——48×48 网格、纯 Python、CPU 可跑、笔记本即可复现与演示，不依赖超算、GPU 或实验室硬件。

## 三、创新点（我们想做出差异化的地方）

1. **不确定性量化（UQ）作为决策接口（创新①）**
   现有代理模型大多只给"点估计"的羽流预测，但工程决策方不敢用"一个没有把握的数字"。我们用深度集成输出**预测 ± 区间**（PICP / MPIW 度量），风险模块额外输出概率熵。这条在 GCS 领域虽热，但本科层面极少做，差异化真实。

2. **多保真度代理（创新②）**
   用少量"贵但真"的高保真样本（Kimberlina 仿真 / PorePy 模型）去校正大量"便宜但糙"的合成样本，multi-fidelity 神经网络。这是 NRAP、Bianchi 2016 等正规科研范式，方法叙述站得住。

3. **知识引导的合成数据（已落地）**
   参数先验不盲采均匀分布，而是取自真实地质数据库（NATCARB / USGS 的训练信封与实测分布），可审计、可辩护。这部分代码已接通并验证可用。

## 五、难点与风险（如实汇报，请老师把关）

1. **风险三档缺少真实地质真值（最关键）**
   当前风险标签由合成器内的打分函数（基于 Q / k / H 三个无量纲数）定义，并非来自真实泄漏案例或地质师判读。这关系到整个风险模块的科学可信度——**恳请老师帮我们判断：这三个参数是否足以刻画泄漏风险？是否需要引入断层、废弃井、盖层完整性等更关键的地质因素？** 这是团队无地学背景最难以独自判断的一点。

2. **多保真度桥接的前提脆弱**
   创新②依赖"玩具合成器"与"真实物理"之间的结构可对齐。若两者物理结构差异过大，残差校正网络可能失效。我们已将其列为最高风险，计划先用 20 个高保真样本做小实验验证可行性，再决定是否作为正式创新点。

3. **真实高保真数据获取受阻**
   Kimberlina 1.2（NETL 公开数据集，论文为 CC-BY 开放获取）是理想的高保真锚，但其原始数据托管于 EDX 门户、需登录下载，我们当前无法稳定获取二进制。NATCARB 参数先验已接通，但**仍缺"真实场数据"**来真正验证代理模型。若老师能提供校内可访问的高保真封存仿真资源（或协助获取 Kimberlina / PorePy 案例），将直接决定创新②能否落地。

4. **合成数据与真实数据的边界必须诚实标注**
   我们已把"合成数据明确标注、绝不冒充真实"写入项目红线。这一点恳请老师在评审材料时监督，避免出现不实陈述。

5. **团队地学知识缺口 + 多任务并行**
   团队目前偏 AI / 软件背景，地质力学、多相流是明显短板；同时成员还并行其他项目。这是执行层面的风险，我们通过"阶段化交付、随时可停且有产出"的结构化管理应对。
