## 一、30 秒版

这个模型干一件事：**给一张"地质参数 + 井条件"的 3D 表（96×200×24 网格 × 12 个通道），吐出同一张表上的 CO₂ 气相饱和度**。

- 96 = 竖向网格数，200 = 水平网格数，24 = 时间帧数，12 = 输入通道数（渗透率、孔隙度、注入位置……）。
- 输出是 1 个通道：同一批格点上的饱和度（0~1）。
- 它**不是**一帧一帧递推出来的：24 个时间帧和空间一起当作 3D 体积，一次前向全算完。
- 参数量 **33,097,829**，其中 94% 花在 6 个"谱卷积层"上。

一句话：**把"解偏微分方程"换成"在频率域里做 6 次带限的通道混合"。**

---

## 二、看懂它需要的 4 个前置概念

| 概念 | 在这里的作用 | 直白解释 |
|---|---|---|
| 线性层 `nn.Linear` | `fc0`/`fc1`/`fc2` | 对**每个格点独立**做一次"把 12 个数混合成 36 个数"。不看邻居，只看自己。 |
| 卷积 `nn.Conv3d` | U-Net 里的每个块 | 每个格点看**周围 3×3×3=27 个邻居**，加权求和。视野只有 3 格。 |
| 傅里叶变换 `rfftn` | 谱卷积的前半步 | 把一团体积数据拆成"慢变化的大斑块 + 快变化的细纹"的和。拆完每个格子换成"频率坐标"。 |
| 复数乘法 | 谱卷积的权重作用 | 对某个频率成分做一次"缩放 + 转相"。一个复数权重 = 同时控制这个频率的幅度与相位。 |

不需要懂反卷积的数学：`ConvTranspose3d(k=4, s=2, p=1)` 只要记住"**把边长翻倍**"。

## 三、整体流水线（实测形状）

`Net3d` 只是 `SimpleBlock3d` 的一层包装（[ufno.py:192-209](../repro/ufno/ufno.py#L192)）。一次前向实测走过的形状：

| 站 | 形状 | 这一站在干什么 |
|---|---|---|
| 输入 | `(1, 96, 200, 24, 12)` | 通道在最后 |
| `Net3d` 补边 | `(1, 104, 208, 32, 12)` | 竖向补 0、水平与时间复制边缘（见第七节） |
| `fc0` | `(1, 104, 208, 32, 36)` | 12 个物理通道 → 36 个"特征通道"（升维） |
| `permute` | `(1, 36, 104, 208, 32)` | 换成 PyTorch 卷积习惯的"通道在前" |
| 第 1~3 层 | 每层 `conv_i` + `w_i` 相加，过 ReLU | 纯 Fourier 层，形状始终 `(1,36,104,208,32)` |
| 第 4~6 层 | 每层 `conv_i` + `w_i` + `unet_i` 相加，过 ReLU | U-Fourier 层（U-FNO 的增量） |
| `permute` 回 | `(1, 104, 208, 32, 36)` | 通道放回最后 |
| `fc1` → ReLU → `fc2` | `36 → 128 → 1` | 逐格点降维成 1 个标量 |
| 裁回 + `squeeze` | `(96, 200, 24)` | 把补出去的 8 格切掉，去掉单通道维 |

中间 6 层的输入输出形状**完全不变**（都是 `(1,36,104,208,32)`），这是算子类网络的特点：它做的是"场 → 场"，不是"图 → 标签"。

## 四、SpectralConv3d：整个模型的心脏

代码只有 20 行（[ufno.py:11-52](../repro/ufno/ufno.py#L11)），逐行看。

### 4.1 它想替代什么

CNN 学的是"空间域里的卷积核"：核越小视野越窄，要看得远就得堆很多层。
FNO 换了个思路，依据**卷积定理**：

> 空间域里做一次"全局卷积"，等价于频率域里对每个频率成分**各乘一个数**。

所以它不学卷积核，直接学"每个频率成分该乘哪个数"。一次乘法 = 全图耦合，**一层就具备全局感受野**。

严格说，频域逐模式相乘对应的是空间域的**循环卷积**（把网格当成首尾相接的环）。这一点很重要，第七节的补边就是为它服务的。

### 4.2 三行主干

```python
x_ft = torch.fft.rfftn(x, dim=[-3,-2,-1])                     # 空间 → 频率
out_ft[..., 选中的模式] = einsum("bixyz,ioxyz->boxyz", 选中的模式, weights)
x = torch.fft.irfftn(out_ft, s=(x.size(-3), x.size(-2), x.size(-1)))   # 频率 → 空间
```

实测：输入 `(1,36,104,208,32)` → `rfftn` 输出 `(1,36,104,208,17)` → `irfftn` 回到 `(1,36,104,208,32)`。
最后一维从 32 变成 17，是因为 `rfft` 只保留非负频率（`N//2+1`）。

### 4.3 为什么权重切成"四个角"

`out_ft` 先整体置零，然后只往四个块里写值（[ufno.py:40-48](../repro/ufno/ufno.py#L40)）：

```
[:m1,  :m2]   [-m1:, :m2]   [:m1,  -m2:]   [-m1:, -m2:]      每个块再取 [:m3] 个时间频率
```

- 频率数组的**开头**是低频（正向小频率），**结尾**是绕回来的负频率（`fft` 把频率按 0,1,…,N/2,-N/2,…,-1 排列）。所以"最后 10 个"同样是低频。
- 两个方向各取头尾 → 组合出 4 个角块。这就是那 4 组权重 `weights1..4` 的来历，不是"4 层"。
- 时间轴只取头 `[:m3]`，因为 `rfft` 没有负频率，不需要绕回。

`modes1=modes2=modes3=10` 的含义：**只让 10×10×10 个低频格子有参数，其余一律清零**。

实测能量核对（样本 0 的真值体积，按 `Net3d` 的补边规则补齐后做 `rfftn`）：

| 指标 | 数值 |
|---|---|
| 频率格子总数 | 104×208×17 = **367,744** |
| 被权重触及的格子 | 4×10×10×10 = **4,000**（**1.09%**） |
| 这 1.09% 格子携带的能量 | 前 8 个样本平均 **88.4%**（区间 82.7%~93.4%） |

配图：`results/ufno_internals/figB_fourier_modes.png`（左：真值频谱的 log 幅值 + 4 个角块框；右：一层谱卷积真正会乘权重的格子）。

**结论**：羽流是"大斑块"场，能量高度集中在低频，所以只保留 1.09% 的模式就够描述绝大部分内容。这既是 FNO 参数效率的来源，也是它的**天花板**（见 4.6）。

### 4.4 `einsum("bixyz,ioxyz->boxyz")` 在做什么

对**每一个被保留的频率三元组** `(x,y,z)`，做一次 `36×36` 的复数矩阵乘：

```
out[b,o,x,y,z] = Σ_i  in[b,i,x,y,z] · W[i,o,x,y,z]
```

所以每个频率格子有自己的一套 36×36 混合矩阵 —— **不同频率用不同的权重**，这是它比普通"全图共享一个核"的卷积更灵活的地方；代价是参数量 = 模式数 × 36 × 36。

### 4.5 权重形状、初始化

```python
weights1.shape = (36, 36, 10, 10, 10)   dtype = torch.complex64
scale = 1 / (in_channels * out_channels) = 1/1296 = 0.0007716
weights = scale * torch.rand(...)        # 均匀分布 [0,1)，实部虚部各一个
```

- 单个 `SpectralConv3d` 参数量 = 4 × 36 × 36 × 10 × 10 × 10 = **5,184,000**。
- 注意口径：`count_params()` 把**一个复数当 1 个参数**。若按实数自由度算，6 层谱卷积是 62,208,000 个实数，总自由度约 **6,420 万**。答辩若被问"33M 是不是虚高/虚低"，就答这个口径差。

### 4.6 参数与网格尺寸无关（FNO 的核心卖点）

权重形状里只有 `(modes, width)`，**没有 104/208/32**。换分辨率不用改一层参数，只要 `modes ≤ 该轴 rfft 长度`。这是它比 CNN 更适合"训练一套网格、预测另一套网格"的原因。
但本仓库的 `Net3d` 把补边量 `+8` 写死了（[ufno.py:206-208](../repro/ufno/ufno.py#L206)），换网格尺寸时要同时检查补边逻辑与 `modes` 上限，不是零成本。

### 4.7 高频被清零了，谁来补？

`out_ft` 初值是 0，谱卷积的输出**不含任何高频**。那高频从哪回来？两条路：

1. **ReLU**：非线性会把低频信号"折"出高频成分；
2. **旁路 `w0..w5`**：`nn.Conv1d(36, 36, 1)` 作用在**空间域**（把 104×208×32 摊平成 692,224 个格点，逐格点做一次 36→36 线性混合，[ufno.py:153](../repro/ufno/ufno.py#L153)）。它不过 FFT，所以高频原样通过。

这就是 FNO 的标准结构 `x = 谱变换(x) + 线性变换(x)`。参数量只有 **1,332/层**（36×36 权重 + 36 偏置），却补住了截断的漏洞。

## 五、SimpleBlock3d：六层怎么拼起来

代码 [ufno.py:108-190](../repro/ufno/ufno.py#L108)。

```python
x = self.fc0(x); x = x.permute(0,4,1,2,3)      # 12 → 36 通道，换轴
x1 = self.conv0(x); x2 = self.w0(...)          # 谱路 + 旁路
x  = F.relu(x1 + x2)                           # 第 1 层
... conv1/w1、conv2/w2 同构 ...                 # 第 2、3 层：纯 Fourier
x  = F.relu(self.conv3(x) + self.w3(x) + self.unet3(x))   # 第 4 层：U-Fourier
... unet4、unet5 同构 ...                       # 第 5、6 层
x  = self.fc2(F.relu(self.fc1(x.permute(0,2,3,4,1))))     # 36 → 128 → 1
```

| 层 | 谱卷积 | 旁路 | U-Net | 这一层的名字 |
|---|---|---|---|---|
| 1~3 | `conv0..2` | `w0..2` | — | **FNO 层** |
| 4~6 | `conv3..5` | `w3..5` | `unet3..5` | **U-Fourier 层** |

**U-FNO 相对 FNO 的全部改动，就是后三层各加了一个 `unet_i` 并把两路相加改成三路相加。** 官方 docstring 也这么写（[ufno.py:112](../repro/ufno/ufno.py#L112)："U-FNO contains 3 Fourier layers and 3 U-Fourier layers"）。

为什么加 U-Net（论文的说法 + 代码可验证的事实）：
- 谱路是**带限**的，锐利边界（羽流前缘）表达吃力；U-Net 在空间域工作，且带跳连，擅长保留边缘与局部细节。
- 两路**并联相加**而不是串联：谱路负责全局低频，U-Net 负责局部高频，互不阻塞梯度。

`ReLU` 放在求和之后：让三路先"合议"再决定激活，若各自先激活再相加会破坏并联语义。

通道数 `width=36`、层数 6 是官方权重定死的，不是本项目调出来的。

## 六、U_net：模型里的"空间域小 U-Net"

代码 [ufno.py:54-104](../repro/ufno/ufno.py#L54)。它**不是**图像分割那种多通道 U-Net，而是一个固定 36 通道的 3 层金字塔。实测内部形状（输入 `(1,36,104,208,32)`）：

| 步骤 | 输出形状 | 说明 |
|---|---|---|
| `conv1` (k3,s2,p1) | `(1,36,52,104,16)` | 下采样 ①：边长减半 |
| `conv2` (s2) → `conv2_1` (s1) | `(1,36,26,52,8)` | 下采样 ②（两步：先减半再原地细化） |
| `conv3` (s2) → `conv3_1` (s1) | `(1,36,13,26,4)` | 下采样 ③：最深层 |
| `deconv2` (ConvTranspose3d k4,s2,p1) | `(1,36,26,52,8)` | 上采样，边长翻倍 |
| `cat(out_conv2, deconv2)` → `deconv1` | `(1,36,52,104,16)` | 通道 36+36=**72** |
| `cat(out_conv1, deconv1)` → `deconv0` | `(1,36,104,208,32)` | 通道 72 |
| `cat(x, out_deconv0)` → `output_layer` Conv3d(72→36,k3,s1) | `(1,36,104,208,32)` | 回到原形状 |

三个要点：

1. **`k=4, s=2, p=1` 为什么正好翻倍**：`out = (in-1)·2 - 2·1 + 4 = 2·in`。13 → 26 也成立，所以奇数尺寸不会被卡住。
2. **跳连是 `torch.cat`（拼接）不是相加**：所以上采样层的输入通道是 72。这是它参数量比"纯卷积堆叠"大的原因，也是 U-Net 能保住边缘信息的机制——浅层细节原样传上来，由后面的 `output_layer` 决定怎么用。
3. **推理时的 BatchNorm / Dropout**：每个 conv 块是 `Conv3d(bias=False) → BatchNorm3d → LeakyReLU(0.1) → Dropout`。
   - 我们跑的是 `model.eval()`：BatchNorm 用训练时冻结下来的 `running_mean/var`，与 batch 大小无关（所以 batch=1 也安全）；
   - `dropout_rate` 传的是 **0**（[ufno.py:139-141](../repro/ufno/ufno.py#L139)），Dropout 实际不生效。

单个 `U_net` 参数量手算（与实测 660,168 一致）：

```
5 个 conv 块：每块 36·36·27 = 34,992 权重 + BN 72 = 35,064      → 175,320
deconv2：36·36·4³ = 82,944 + 36                                  →  82,980
deconv1/deconv0：72·36·4³ = 165,888 + 36，各一个                 → 331,848
output_layer：72·36·27 = 69,984 + 36                             →  70,020
                                                          合计    = 660,168
```

## 七、Net3d 的补边与裁回（最容易看错的两行）

```python
x = F.pad(F.pad(x, (0,0,0,8,0,8), "replicate"), (0,0,0,0,0,0,0,8), 'constant', 0)
x = x.view(batchsize, size_x+8, size_y+8, size_z+8, 1)[..., :-8,:-8,:-8, :]
```

**`F.pad` 的元组顺序是从最后一个维度往前数**，这是最常见的读错点：

| 调用 | 维度 | 96/200/24 → | 补法 |
|---|---|---|---|
| 第一个 `F.pad` 第 3 对 `(0,8)` | dim −3 = 水平 200 | 208 | `replicate`（复制边缘值） |
| 第一个 `F.pad` 第 2 对 `(0,8)` | dim −2 = 时间 24 | 32 | `replicate` |
| 第一个 `F.pad` 第 1 对 `(0,0)` | dim −1 = 通道 12 | 12 | 不动 |
| 第二个 `F.pad` 第 4 对 `(0,8)` | dim −4 = 竖向 96 | 104 | 常数 0 |

**为什么要补边**（代码没写注释，以下是从机制推出的解释，标注为推断）：
谱卷积对应的是**循环**卷积——FFT 默认网格首尾相接。如果羽流正好压在边界上，"右边缘接左边缘"会造出一个物理上不存在的跳变，产生虚假高频。用 `replicate` 把边缘值向外复制 8 格，等于给边界留出缓冲区，让 FFT 的周期假设不再撕裂场；竖向补 0 则是因为上覆层本来就是哨兵 0（见第八节），补 0 不引入新跳变。算完再用 `[..., :-8, :-8, :-8, :]` 把缓冲区切掉，只留原始 96×200×24 区域。

顺带两个坑：
- `x.squeeze()`（[ufno.py:209](../repro/ufno/ufno.py#L209)）会把**所有**长度为 1 的维度去掉：batch=1 时输出变成 `(96,200,24)`，batch>1 时是 `(B,96,200,24)`。所以 [eval_ufno_gas_saturation.py:87](../repro/ufno/eval_ufno_gas_saturation.py#L87) 用 `.view(-1,96,200,24)` 兜住两种情况。
- 补边量 `+8` 与 `modes=10` 是绑死的：`modes` 必须 ≤ 该轴 `rfft` 长度（时间轴 32 → 17）。

## 八、输入 12 通道与输出到底是什么

`fc0` 的 docstring 给出通道顺序（[ufno.py:122-126](../repro/ufno/ufno.py#L122)）。本机实测范围（test 集前 20 个样本，`tools/ufno_internals_probe.py` 同款读法）：

| 通道 | 含义 | 实测取值范围 | 结构特征 |
|---|---|---|---|
| ch0 | ln(水平渗透率)/15 | −0.3799 ~ 0.6100 | **储层外为精确 0**（哨兵）；储层内 −0.0153~0.4774 |
| ch1 | ln(竖向渗透率)/15 | −0.6799 ~ 0.3042 | 同上，各向异性来源 |
| ch2 | 孔隙度 | 0 ~ 0.2558 | 储层内 |
| ch3 | 注入位置 | 0 ~ 1 | 稀疏标记（样本 0 仅 168 个非零格点） |
| ch4 | 注入速率 | 0.0471 ~ 0.9611 | **整场一个常数**（样本 0 = 0.93305） |
| ch5 | 温度 | 0.0286 ~ 0.8355 | |
| ch6 | 压力 | 0.0255 ~ 0.9901 | |
| ch7 | Swi（束缚水饱和度） | 0.1678 ~ 0.9906 | |
| ch8 | 流度比 λ | 0.0139 ~ 0.9306 | |
| ch9/10/11 | 水平/竖向/时间格距 | 0 ~ 1 | 归一化坐标，随位置单调变化 |

渗透率还原：`kr = exp(ch0 × 15)` mD（官方 notebook 的画图代码就是这么反归一化的）。

**掩膜（mask）**：官方把"哪些格点属于储层"直接定义成 `ch0 != 0`（[eval_ufno_gas_saturation.py:86](../repro/ufno/eval_ufno_gas_saturation.py#L86)）。样本 0 实测：竖向第 0~51 行是储层（共 **52 行 / 96 行 = 54.17%**），第 52~95 行是哨兵 0 的上覆区。所有指标都只在掩膜内计算。

**输出**：气相饱和度，真值范围 0~1（样本均值 0.0253）。模型输出**没有做 clamp**，实测样本 0 的预测落在 −0.0065 ~ 1.0024，轻微越界属正常。

**物理尺度**（按官方 notebook 的格距公式复算）：
- 水平格距 `dx_i = 3.5938 × 1.035012^i` m，从 3.6 m 指数加粗到 **3,386 m**，累计域长 ≈ **100 km**。
- 时间步长 `cumsum(1.421245^i)` 天，24 步累计 10,950 天 ≈ **30 年**，前密后疏（第 1 步 0.1 天，末步约 4.5 年）。
- 竖向没有可在官方代码中还原的物理公式（只有归一化格距通道 ch10），因此**不宣称竖向米数**。
- ⚠️ 更正：`docs/数据集与结题可行性审计.md` 第二节写的"水平约 3500 m"是把"最大单格距"当成了"域长"，实际域长约 100 km。

## 九、参数量账本（手算 + 实测）

| 模块 | 单个 | 个数 | 小计 | 手算式 |
|---|---|---|---|---|
| `SpectralConv3d` | 5,184,000 | 6 | **31,104,000** | 4 × 36×36×10×10×10 |
| `U_net` | 660,168 | 3 | **1,980,504** | 见第六节 |
| `w0..w5`（1×1 旁路） | 1,332 | 6 | **7,992** | 36×36 + 36 |
| `fc0` | 468 | 1 | 468 | 12×36 + 36 |
| `fc1` | 4,736 | 1 | 4,736 | 36×128 + 128 |
| `fc2` | 129 | 1 | 129 | 128×1 + 1 |
| **合计** | | | **33,097,829** | 与 `count_params()` 实测一致 |

配图 `results/ufno_internals/figA_param_breakdown.png`。

三个可直接背下来的结论：
1. **94% 的参数在 6 个谱卷积层**，模型本质是"频域通道混合器"，U-Net 只占 6%。
2. **升维/降维几乎不花钱**（fc 三层共 5,333 个，占 0.016%）——算力花在 6 次 FFT 上，不是花在 fc 上。
3. 参数量与网格分辨率**无关**（权重形状里没有 104/208/32），但**与 modes 三次方相关**：`modes 10→20` 会让每层权重变成 8 倍（5,184,000 → 41,472,000）。

## 十、训练时它在学什么（我们不复现，但要能讲）

[train_ufno_gas_saturation.py:80-97](../repro/ufno/train_ufno_gas_saturation.py#L80) 的损失是两项：

```python
ori_loss = 相对 L2(pred[mask], y[mask])          # 场本身
der_loss = 相对 L2(d_x pred[mask], d_x y[mask])  # 沿水平方向的差分（导数）
loss     = ori_loss + 0.5 * der_loss
```

- 导数项 `dy = (y[:,:,2:,:] - y[:,:,:-2,:]) / grid_dx` 用真实格距做中心化差分，**逼模型把羽流前缘的梯度学对**，而不是只把整体形状学像。这是论文里"锐利边界更准"的直接原因。
- 优化器 Adam(lr=1e-3, weight_decay=1e-4)，StepLR(step 2, γ 0.9)，论文 100 轮。
- 我们走"官方权重 + 推理"路线，所以这套损失只在答辩被问"它怎么训出来的"时使用；本机不训练（训练集 ≈99.5 GB）。

| 用途 | 入口 | 关键点 |
|---|---|---|
| 复现精度 | [repro/ufno/eval_ufno_gas_saturation.py](../repro/ufno/eval_ufno_gas_saturation.py) | 官方权重 + test 500 样本 → 掩膜相对 L2 **0.0647** |

| 内部结构实测 | [tools/ufno_internals_probe.py](../tools/ufno_internals_probe.py) | 本文所有形状/参数/能量数字的出处 |
| 不确定性量化 | [src/uq_model.py](../src/uq_model.py) | **扰动输入通道而不是权重**：ch0/ch1（ln 渗透率）、ch2（孔隙度）、ch4（注入速率）、ch7（Swi）、ch8（流度比），且只在掩膜内扰动；ch3 井位、ch5/6 温压、ch9/10/11 网格视为已知边界不动 |

为什么 UQ 要扰动输入而不是权重：官方只发布 1 组权重，深度集成必须自训 K 个成员，而训练集本机放不下。扰动输入通道正好利用第八节的通道语义——**每个被扰动的通道都有明确物理含义**，所以区间可以被解释为"渗透率/孔隙度不确定 → 羽流不确定"，这是答辩里 UQ 部分最硬的一句话。

## 十二、六个常见误解（答辩追问）

1. **"U-FNO 是 FNO 堆深一点"** → 不是。层数一样（6 层），改的是后 3 层各并联一个 U-Net 分支。
2. **"FFT 让它不用训练就能泛化"** → 频域参数化只是让全局耦合便宜；泛化仍来自数据。它的泛化边界是**训练时的参数分布**。
3. **"保留全部频率才准，截断是丢信息"** → 实测 1.09% 的格子承载 88.4% 的能量；截断换来的是参数效率与噪声抑制，代价是锐利边界要靠 U-Net 分支和导数损失补。
4. **"它能任意换网格尺寸"** → 权重形状确实与尺寸无关，但 `Net3d` 的 `+8` 补边写死、`modes ≤ rfft 长度` 有硬约束，换尺寸要检查这两处。
5. **"输出是物理饱和度，一定在 0~1"** → 没有 clamp，实测 −0.0065~1.0024。越界幅度极小，但讲"区间"时不能用 [0,1] 去截断它。
6. **"时间维是自回归推进的"** → 不是。24 帧与空间一起当第三维一次算完（3D 体积），所以它不能"预测到 25 年"——超出训练时间轴就是外推。

## 十三、动手实验（每个都有预期现象）

按顺序做，做完就真懂了这个模型：

1. **看形状**：跑 `tools/ufno_internals_probe.py`，对照本文第三、六节的表。10 分钟。
2. **随机权重 vs 官方权重**：把 eval 脚本里 `torch.load(...)` 那行临时换成 `Net3d(10, 10, 10, 36)`（不加载权重），其余不动，重跑 `--limit 20` → rel L2 从 0.0647 变成 ≈1.0~1.2（此数字已实测；`tools/bench_gpu_inference.py` 用的就是这种随机初始化模型，但它只计时不算指标）。→ 理解"指标不是代码跑出来的，是权重学出来的"。
3. **误读目标张量**：把 `sg_test_u.pt` 按 C 序朴素 reshape 再算指标 → rel L2 **2.85**、相关性 0.00（已实测）。→ 理解"这类错误不报错，只给你一个看着差不多的坏指标"。
4. **砍掉 U-Net 分支**：把 `SimpleBlock3d.forward` 里 `x3 = self.unet3(x)` 等三行注释掉、并去掉求和中的 `+ x3`（权重 pickle 里那些 unet 参数变成未使用，不影响加载）。→ 这是亲手量出"U-FNO 比 FNO 强多少"的唯一办法；预期整体指标变差、羽流前缘更明显，**幅度要自己实测后写进答辩，别引用别人的数**。
5. **改 modes**：官方权重是**整模型 pickle**，`torch.load` 直接返回训练好的对象，结构由文件决定。若把 `Net3d(10,10,10,36)` 换成 `(5,5,5,36)` 再搬权重，会因 `weights*` 形状从 `(36,36,10,10,10)` 变 `(36,36,5,5,5)` 而明确报 size mismatch。→ 反过来验证 4.6 节"参数量 ∝ modes³"。
6. **看频谱**：把 `figB_fourier_modes.png` 左图换成你自己的预测场（改 `u[0]` 为 `pred`），观察高频残余 → 直观看到"模型把羽流写平滑了"。
